## Project

Max App Limiter is a personal Android-only parental-control app (Expo SDK 58, Expo Router, TypeScript, plus a local
Kotlin module). A parent sets a master password and gives apps a daily time allowance; when it is used up the app
is covered by a block screen, where "More time" asks for the password. Allowances reset at local midnight. The
limited person is a child, so resisting bypass is a requirement, not a nice-to-have. There is no backend and no
account. The UI is English. Ideas that are not built yet are in `docs/ROADMAP.md`.

```bash
npx expo prebuild -p android --no-install                 # generates android/ (gitignored)
(cd android && ./gradlew :app-limiter:testDebugUnitTest)  # Kotlin unit tests (Limits.kt)
(cd android && ./gradlew :app:assembleDebug)              # debug APK, needs Metro (npm start) to run

npx eas-cli@latest build -p android --profile preview     # standalone APK in the cloud
```

`android/` is generated by `expo prebuild` and gitignored: configure native behavior through `app.json` and the
module's own manifest, never by editing `android/`. The app does nothing in Expo Go (the native module is `null`
there and the lock screen says so).

## Architecture

- **Native is the source of truth.** Rules, usage, granted time and the password hash live in SharedPreferences
  (`max_app_limiter`), owned by `modules/app-limiter` (`LimiterStore.kt`). The block screen has to check the
  password and grant time while the React Native app is not running, so JS never holds state of its own: it
  mirrors `AppLimiter.getState()` in a zustand store (`src/limiter/store.ts`) and re-reads after every change.
  There is no database.
- **Decisions are pure.** `Limits.kt` has no Android imports: `decide(pkg, now, tz, state)` returns
  `Allow(recheckMs, rule, remainingMs)` or `Block(reason)` with reason `LIMIT`, `BEDTIME` or `LOCKED`, and
  `grant(...)` computes what "more time" changes. It is covered by JUnit tests
  (`modules/app-limiter/android/src/test`). `src/logic/rules.ts` mirrors the allowance maths for display only;
  keep the two in sync (also `formatDuration`).
- **Rules.** A rule is `{ id, name, packages[], minutesByDay[7] (Monday first), enabled }`. A single-app limit is
  a rule with one package; a group is a rule with several that share one allowance. A package belongs to one rule
  only (`LimiterStore.saveRule` removes it from the others and drops rules left empty). Schedules are just
  `minutesByDay`; the editor shows it as "every day", "weekdays / weekend" or "each day" (`scheduleKind`,
  `applySchedule`).
- **Days.** Usage and extra time are stored per local calendar day (`usage[day][package]`, `extra[day][ruleId]`,
  30 days kept). A new day starts from zero because the key changes; there is no midnight job. The service's
  recheck delay is capped by the time to midnight, so a session across midnight is split correctly.
- **Service.** `LimiterService` (AccessibilityService, `TYPE_WINDOW_STATE_CHANGED` only, window content is never
  read) tracks the foreground package, ignoring keyboards and `com.android.systemui`. Every tick
  (`min(remaining, time to midnight, 30 s)`) it commits the elapsed time, so a killed service loses at most one
  tick. Counting stops while the screen is off or the keyguard is up. It warns once per allowance `warnMinutes`
  before the end (Toast plus notification). Blocking starts `BlockActivity` and deliberately does not send the
  user home first (the home screen would arrive later and cover the block screen).
- **Block screen.** `BlockActivity` is plain Android views built in code (no React Native), in its own task
  (`taskAffinity`, `singleTask`, `excludeFromRecents`). Back and Close go to the home screen. "More time" →
  5/15/30/60 min or rest of today → password (PBKDF2, checked off the main thread) → `LimiterStore.grant` →
  `finish()`, which reveals the blocked app underneath; `LimiterService.onUnblocked` restarts counting because
  that return raises no reliable window event.
- **Password.** PBKDF2-HMAC-SHA1 with a random salt. Five free wrong tries, then a wait that doubles from 30 s
  up to 15 min. It cannot be recovered. JS gets a session token from `unlock`/`createPassword`; every call that
  changes configuration or opens a system screen takes the token and throws `ERR_LOCKED` without it. Nothing is
  enforced until a password exists.
- **Tamper protection.** (1) The app locks whenever it goes to the background (`lockOnBackground` in the root
  layout), except for up to 2 minutes when it opened a system screen itself (`expectSystemTrip`). (2) Locked
  apps always show the block screen: Settings and the package installers by default (`lockSettings`,
  `SYSTEM_PACKAGES`), plus any the parent picks. A password unlock lasts as long as chosen; the module unlocks
  Settings for 5 minutes when the unlocked app sends the parent there. (3) Optional device admin
  (`AdminReceiver`, no policies) so Android refuses to uninstall the app. Pausing limits does not unlock locked
  apps.
- **Bedtime and pause.** Bedtime blocks every package that has a rule inside a daily window (may cross
  midnight); a grant during bedtime unlocks the rule's packages and tops the allowance up to the granted time.
  `pauseUntil` lifts limits and bedtime but keeps counting usage.
- **Navigation.** expo-router ships its own fork of react-navigation, so don't install `@react-navigation/*`.
  Tabs come from `expo-router/js-tabs` (`src/app/(tabs)`: Limits, Usage, Settings); `rule/[id]` (`id` = `new`
  for a new rule), `pick-apps` and `change-password` are stack screens. `LockGate` is rendered above the stack
  while there is no session token.
- **Editing a rule.** The editor works on a draft (`src/limiter/draft.ts`) so the app picker can change the
  packages before anything is saved. `pick-apps?target=rule` edits the draft; `pick-apps?target=locked` saves
  the locked list immediately.
- **App icons** in lists come from `getLaunchableApps`, which renders each launcher icon once into
  `cacheDir/app-icons/<package>.png` and returns file URIs. The module's manifest has a launcher `<queries>`
  entry instead of `QUERY_ALL_PACKAGES`.

## Rules

- Never commit or push without asking the user first.
- Native changes need a new build; a JS reload is not enough.
